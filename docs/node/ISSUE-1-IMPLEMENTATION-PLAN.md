## 1. 目标、阶段与约束

第一阶段：副面板从主面板读取指定入站的客户端，让新增 UUID、启用状态和支持的客户端字段自动在副节点生效。

第二阶段：副面板本地出站管理、路由管理与指定出站测试。第三阶段才研究 DNS、GeoIP/GeoSite、规则集和可视化。

约束：

- 不修改主面板生产代码或主面板数据；唯一前置配置是用户提供专用主面板 API Token。
- 副面板访问主面板只允许固定的 GET 读取接口，禁止复用具备任意写请求能力的管理客户端。
- 保持 Alpine/OpenRC、单个副面板 Go 服务加现有 Xray 子进程的部署方式。同步器放在既有服务内。
- 维持当前 8 入站、64 个唯一 email 客户端限制；超限明确报错，不截断、不默默丢客户端。
- 不承诺当前 128 MiB 环境已通过长期生产验收；当前监控快照不能替代负载测试。
- 默认不删除主面板已移除的本地客户端。这意味着撤销不会自动完成：菜单必须清楚显示待清理与仍可访问的风险，不能宣称完全自动撤销。

关键事实：

1. node-sync Token 允许 GET `/panel/api/inbounds/list`，不允许 `/clients/list` 或 `/inbounds/get/:id`。monitor 无权读取完整客户端，admin 权限过大；不能假设所有读取接口都能用。
2. `Object` 已兼容 JSON 对象和 JSON 字符串格式，优先复用此能力。
3. `State.Traffic` 按 email 共用，`SyncClients` 要求同 email 的 UUID/配额/到期/启用状态一致。
4. `ChangeClient(update)` 会修改多个入站中同 email 的客户端，不能直接用于隔离的拉取同步。
5. `transaction` 已负责采样、克隆、校验、应用、落盘与恢复；新同步必须走同一事务路径。
6. 客户端热更新有失败后重启恢复的分支；结构变化本身会重启。不能承诺任何故障都不中断连接。

## 3. 必须先完成的契约验证（A0）

不要把“文档有 clients 字段”当成线上返回一定包含正确主客户端 UUID 的证据。

先编写脱敏契约测试：使用现有主面板测试设施，在主面板模型中建立一个远端 VLESS 入站并绑定客户端，通过真实 list handler + node-sync 鉴权取回响应。验证 `settings.clients` 是否包含绑定客户端的 UUID、email、enable，而非仅副节点镜像或 clientStats。

- 检查创建绑定之后、远端同步之前/之后返回是否一致；避免主面板返回的仍是副节点旧客户端，造成循环复制。
- 正文嵌套对象和字符串两种格式都要覆盖。
- 若该接口不返回可信的绑定客户端，不继续写同步器。先只读调查其他现有读取接口/权限，报告所需权限和能力差距；不得擅自修改主面板或换用 admin Token。
- 线上验证须使用用户本机提供的 Token；不要求用户在聊天粘贴 Token，不保存原始 API 响应到公开仓库。

通过标准：有可重复的测试证明，新增一个主客户端绑定会出现在拉取响应中。此项是 A1–A6 的前提。

## 4. 同步功能设计

### 4.1 配置、映射与秘密存储

建议 `Config` 添加可选 `masterSync`：enabled（默认 false）、baseURL、tokenFile、certSHA256、intervalSeconds（默认 60，允许 30–3600）、mappings。

- 首版只支持一个主面板源、最多 8 个显式映射；每个本地入站只能属于一个映射。
- baseURL 是协议、域名/端口和面板随机前缀组成的根地址，不包含 `/panel` 或 `/api-docs`；向导可识别用户粘贴的完整文档地址，展示归一化结果后确认。
- 每个映射有稳定 mappingID、masterInboundID、localInboundID，以及绑定时记录的源/目标 tag、protocol、本地 GUID 等身份信息。tag 用于身份核验，不用于自动猜 ID。
- 入站删除重建、ID 回收或身份变化时停止该映射，要求重新确认。不能把旧 ID 自动指向新入站。
- 主 Token 独立存储于仅 root 可读的文件，目录 0700、文件 0600；配置仅存路径。拒绝不安全的文件所有者/权限和符号链接。
- 向导用终端无回显输入；非终端输入使用受控文件/stdin，不将 Token 作为 CLI 参数。状态、预览、日志和错误不能包含 Token、UUID、完整 URL 查询或响应正文。
- 首次证书指纹须由用户从可信渠道提供并确认。自动获取可用于展示，不能将首次获取直接当作可信认证。
- 配置变更通过本地管理接口校验并热加载同步器；只替换同步配置快照，不并发修改服务 Config。源地址/证书/映射变更让旧请求结果失效。

### 4.2 最小只读 HTTP 客户端

建议新文件 `internal/node/master_reader.go`，只暴露 FetchInbounds(ctx)，不暴露任意 URL/方法。

- 固定 GET，路径由规范化根地址拼接 `/panel/api/inbounds/list`。
- HTTPS：正常证书链/主机名验证 + SHA-256 指纹校验；证书更换时停止同步并提示更新指纹，不自动接受新证书。未来若需要自签证书，用显式可信 CA 配置，不开放跳过校验开关。
- 禁止 HTTP 重定向，禁用自动环境代理，避免 Token 被转发到非预期主机。
- 总超时建议 10 秒；响应解压后上限建议 4 MiB，通过 limit+1 判超限，不仅检查 Content-Length。避免缓存其他入站的秘密字段。
- 验证 HTTP 状态、success 布尔值、obj 类型和 JSON 完整性。缺字段、重复目标 ID、HTML 登录页、null、超限、401/403 均为错误，绝不能转成空客户端列表。
- 用最小 DTO，仅解析必要字段；其他协议入站可以跳过，但目标入站必须是兼容 VLESS。
- 403 提示 Token 范围不足，不自动换接口/提升权限。429 尊重有上限的 Retry-After。

### 4.3 字段同步与身份冲突

| 字段 | 首版行为 |
| --- | --- |
| id / email / enable | 必须有效；照主配置同步，UUID 不能自动生成替代 |
| flow | 空或 Vision；检查本地 REALITY/DisableFlow，不兼容报错 |
| totalGB | 已有模型中的字节配额，禁止再乘 GB；缺失按 0 处理仅限已确认契约 |
| expiryTime | 毫秒；负值首次使用语义须沿用并测试现有激活流程，已激活客户端不能每次拉取重新归零或延期 |
| subId / comment 等 | 只保留现有校验允许的必要元数据，缺失可选字段不清掉无关本地字段 |
| trafficReset / trafficResetDay | 按现有支持范围；非 never 的自动重置报不支持 |
| IP/HWID/设备限制等 | 非零或启用时明确报不支持，禁止静默剥掉访问限制 |
| up/down/lastOnline/clientStats | 不作为本地累计计数覆盖来源；沿用已有流量统计和 Globals 通道 |

首次只接受同 UUID+email 的无冲突匹配；同 email 不同 UUID、同 UUID 不同 email、跨非托管入站共享 email 的不兼容变化，都返回冲突详情并保留现状。

对已经确认由同步器管理的客户端，UUID 轮换可作为更新，但若共享的非托管入站会受到影响，整批拒绝。email 重命名首版要求人工迁移，不能自动删建而清空计数或重置配额。

### 4.4 所有权与主面板推送并存

这是本功能最关键的设计：既有主面板仍可能 POST 入站或客户端，不能让后台轮询和主面板推送反复覆盖。

- 在 State 增加可选同步元数据：映射身份、受管理 email/UUID 集合、最后成功应用的规范化字段。与客户端配置在同一个事务保存。
- 同步不开启时，所有现有行为保持兼容。
- 启用映射需要预览本地客户端：完全一致的现有客户端可明确收编；其他客户端保持手工管理，不能默默取得所有权。
- 托管映射的客户端以拉取结果为准。主面板推送的非客户端入站字段仍按原校验处理；推送中的 clients 不覆盖该映射客户端，返回可识别的同步所有权冲突/提示，避免假报客户端写成功。
- 托管客户端的 add/update/delete/detach（包括菜单 13/14）经统一保护检查；冲突写入明确返回冲突，用户须先解除相应托管。未托管入站正常处理。
- 明确删除整个入站允许执行，但同一事务停用其映射并清理映射元数据；同步器绝不重建被删入站。
- 托管映射禁用默认客户端注入，其他入站继续支持 default-client。默认兜底不能把主面板的合法空客户端列表变成可用账号。
- 解除托管只释放所有权、保留现有客户端，不自动回滚到陈旧列表。
- 模拟未修改主面板收到冲突响应后的重试/导入行为；若形成无限重试或主端不断失真，必须报告该兼容问题，不能仅凭一次同步成功宣布完成。

### 4.5 预览与原子应用

建议 `sync_diff.go` 为纯函数，输入本地快照、可信远端快照、映射，输出 add/update/unchanged/pendingRemoval/conflict；默认输出隐藏 UUID。

- 明确区分目标缺失、clients 字段缺失、合法 `clients: []`。后者仅标记已托管成员待清理，前两者报错。
- 远端已删除的客户端按 Issue 保留且标为待清理；远端明确 enable=false 则正常停用。
- 待清理提供显式确认后的本地清理操作，仅针对托管成员，不影响手工客户端和其他入站；不能因为源读失败而自动触发。
- 先在锁外请求远端；取得结果后在 transaction 内基于最新本地状态重新计算差异。禁止网络请求期间持有 n.mu。
- 首版每轮所有启用映射作为一批：任一配置冲突则整批不应用，不出现前一半成功后一半失败。
- 校验配置版本和映射身份，丢弃旧配置发起的请求结果；并发 push/菜单修改不能被旧预览覆盖。
- 一次 clone、一次校验、一次 Engine.Apply、一次状态保存；不循环调用 ChangeClient。
- 未变化时不改客户端/所有权状态、不重启、不因为成功时间戳反复写 state；统计本身的正常采样写入不受此要求影响。
- 沿用现有 ErrDurability 和恢复策略。错误报告区分拉取失败、校验失败、应用失败、落盘/回滚失败，不能一律承诺服务不中断。

### 4.6 调度与菜单

- 服务启动先恢复本地 Xray，再异步启动同步器，主面板离线不得阻塞本地启动。
- 一个 worker，定时/手动同步共用互斥入口，不并行运行；60 秒默认间隔，失败指数退避到最多 15 分钟并加少量抖动。成功恢复正常间隔。
- SIGTERM 取消 HTTP 请求、关闭空闲连接、等待 worker 退出，复用主服务生命周期。
- 最近成功时间和计数在内存维护；服务重启后标注“本次启动尚未同步”，避免伪装为持久化历史。
- 本地同步 API 必须检查实际 socket 对端为回环地址并验证副面板 Token，禁止信任 X-Forwarded-For。现有远程 node Token 不能远程读取或设置主面板 Token。
- 建议命令：`3x-ui-node sync configure|status|preview|now|disable|cleanup`；所有执行由正在运行的服务完成，CLI 不另起一个 Node、不直接改 state 文件。
- 建议新增菜单：15 配置同步、16 同步状态、17 预览差异、18 立即同步、19 停用同步、20 清理待移除客户端；保留现有 13/14 的编号。
- 向导顺序：主地址 → Token → 指纹 → 测试只读访问 → 列出源入站及本地入站 → 明确选择映射 → 预览和所有权确认 → 启用。

## 6. 第一阶段必需测试

使用假 HTTP 服务和 Fake Engine 完成日常单元测试，仅 A5 做真实 Xray 集成和资源验收。

1. 源契约：对象/字符串 settings、绑定真实 UUID、node-sync 权限、空列表与字段缺失的区别。
2. 网络：401/403/429/500、证书指纹错、重定向、超时、超大/压缩响应、HTML、截断 JSON；每种情况本地客户端和计数不变。
3. 差异：新增、禁用、重新启用、托管 UUID 轮换、email 冲突、跨入站共享、重复 ID、超 64 客户端、源入站消失；重复应用幂等。
4. 所有权：主面板空 clients 推送不覆盖托管成员；菜单和远程写入遵守统一保护；删入站不被 worker 复活；非托管入站保留原行为。
5. 配额：既有 up/down 不清零，正/负 expiryTime 不重复延期，默认客户端不插入托管空列表，不支持的访问限制不被静默忽略。
6. 事务：API 与同步同时写、配置切换期间旧 HTTP 返回、保存失败、恢复失败；无部分提交和数据竞争。
7. 真实链路：主面板绑定测试客户端 → 拉取 → 本地配置+运行态具备同 UUID → 客户端经代理访问受控目标；只看 TCP 端口或延迟绿色不算全链路验收。
8. 资源：与 0.1.7 相同环境做 A/B；记录 idle、最大映射/客户端、持续 24h 的 RSS/cgroup 峰值/OOM/磁盘/请求次数，不用 Swap 掩盖内存不足。

```sh

go test -race ./internal/node ./cmd/3x-ui-node

NODE_XRAY_TEST_BINARY=/absolute/path/to/pinned/xray go test -v ./internal/node
```

## 7. 第二阶段：本地出站与路由

前提：A5 通过；独立于客户端同步发布，不把路线一次塞进首个补丁。

### 7.1 范围与模型

- 第一小版：保留 direct，新增 block 与 SOCKS5 代理出站（无认证/用户名密码）。VLESS 上游出站另一个增量，确认固定 Xray 的字段契约后实现，不泛化支持全部协议。
- 新 Outbound：稳定 tag、协议及类型化 settings；保留 api/direct/block 名称，拒绝重复 tag。凭据不在列表/日志显示。
- 新 RoutingRule：稳定 ID、enable、priority、inboundTag、domain、ip/CIDR、port、network、outboundTag。
- 同规则不同字段 AND，同字段多个值 OR；按 priority 顺序匹配，第一条命中；未命中默认 direct。
- 首版“协议”仅 TCP/UDP 网络类型。HTTP/TLS 等应用协议匹配通常依赖嗅探；当前嗅探禁用，不能在菜单暴露一个实际不生效的功能。
- 域名规则仅对 Xray 已知域名有效。客户端只传 IP 时不能保证域名分流；页面/菜单说明此限制。
- 可配置数量上限建议 16 出站/64 规则，不引入 Geo 库；精确域名和后缀规则优先，正则延后。
- 删除被规则引用的出站、删除有路由引用的入站要明确拒绝并列出引用；重命名按同一事务更新引用。
- 主面板客户端/入站更新不得抹掉本地出站与路由；用户规则永远不能接管回环 Xray API 路由。

### 7.2 Engine 与提交语义

现有 Engine.Apply 只接收 LiveInbound，扩展为包含 Inbounds、Outbounds、Routing 的 RuntimeConfig；同步阶段不要提前做这次重构。

- `desired`、Core 配置生成、结构比较、所有 Fake Engine 和集成测试一起迁移。
- 未配置出站/路由时，生成与现状等效的 direct 与保留 API 路由，不更改当前出站访问行为。
- 只改 Users 继续热更新；结构变化先生成临时候选配置，用固定 Xray 的配置检查验证，再由管理员确认后应用。
- “原子保存配置”不等于“连接无损”。首次版本允许经确认重启应用结构变化；显示预计断连，失败尝试恢复旧配置。
- 若要求结构更新不中断现有连接，须另开研究任务验证固定 Xray 的出站/路由动态 API，不能仅写一个临时文件就宣称达标。
- 磁盘失败和回滚失败沿用明确停机/错误策略；任何报告不保证不可恢复故障下连接继续存在。

### 7.3 菜单与指定出站测试

- 21 出站列表、22 添加/编辑/删除出站、23 路由列表、24 添加/编辑/删除/排序路由、25 测试指定出站。
- 向导提供协议所需字段，展示脱敏摘要；保存前检查引用关系，结构应用前提示可能短暂断连。
- 测试必须实际经过选定代理访问受控 HTTP(S) 目标，报告耗时和错误阶段；单纯 TCP 连接代理端口不等于出站可用。
- SOCKS5 可在副面板进程内做有超时的单次探测；block 显示“预期拒绝”。更复杂出站的测试方式独立设计，不在 128 MiB 机器默认启动第二个 Xray。
